## 2. `DebtPayments` — รายการโอนใช้หนี้

| คอลัมน์ | ชนิด | หมายเหตุ |
|---|---|---|
| ประเภทบัญชี | ตัวเลือก | ต้องตรงกับก้อนหนี้ |
| วันที่ชำระ · ปี | วันที่ / ตัวเลข | ระบบเติมปีให้จากวันที่ |
| **เงินต้น** | เงิน | ส่วนที่นำไปลดยอดหนี้จริง |
| **ดอกเบี้ย** | เงิน | ไม่ลดยอดหนี้ แสดงแยกต่างหาก |
| **รวมที่โอน** | เงิน | ระบบคิดให้ = เงินต้น + ดอกเบี้ย ใช้ตรวจกับยอดในสลิป |
| รหัสหนี้ | ข้อความ | เว้นว่างได้ — ระบบจะเฉลี่ยตามสัดส่วนยอดตั้งต้นของแต่ละก้อน |
| สลิปการโอน | ไฟล์ | ลิงก์ Drive คั่นด้วยขึ้นบรรทัดใหม่ |

**สูตรที่ระบบใช้**
```
ยอดหนี้ทั้งหมด = Σ ยอดหนี้ตั้งต้น (เฉพาะบัญชีนั้น)
ชำระแล้ว      = Σ เงินต้น          ← ดอกเบี้ยไม่ถูกนับตรงนี้
ดอกเบี้ยที่จ่าย = Σ ดอกเบี้ย
คงเหลือ       = ยอดหนี้ทั้งหมด − ชำระแล้ว
ความคืบหน้า    = ชำระแล้ว ÷ ยอดหนี้ทั้งหมด × 100

หนึ่งครั้งที่โอนอาจมีทั้งเงินต้นและดอกเบี้ยปนกัน เช่น โอน 32,200 บาท
แยกเป็นเงินต้น 30,000 + ดอกเบี้ย 2,200 — ยอดคงเหลือจะลดแค่ 30,000 เท่านั้น

### ก้อนหนี้ซ้อนกันเป็นแม่-ลูก

ใช้เมื่อเงินก้อนหนึ่งเป็น **ทุน** ของอีกก้อน ไม่ใช่หนี้เพิ่มอีกก้อน

```
ซื้อที่ดิน The M Corner AP   4,700,000        ← ก้อนแม่
  └─ เงินยืมป้าตา (ทุนซื้อที่ดิน)  1,000,000   ← ก้อนลูก (อยู่ใน 4.7 ล้านนั้นแล้ว)
```

| กติกา | ผล |
|---|---|
| จ่ายคืนก้อนลูก 100,000 | ก้อนลูกคงเหลือ 900,000 **และ** ก้อนแม่ลดลง 100,000 ด้วย |
| รวมยอดทั้งระบบ | นับเฉพาะก้อนที่ไม่มีแม่ → 13,151,000 ไม่ใช่ 14,151,000 |
| ดอกเบี้ยของก้อนลูก | ไม่ไหลขึ้นหาแม่ เพราะเป็นค่าใช้จ่าย ไม่ได้ลดเงินต้น |
| ผูกวนกลับมาหาตัวเอง | ระบบปฏิเสธตั้งแต่ตอนบันทึก |

ผูกได้หลายชั้นและข้ามบัญชีได้ (แม่อยู่หนี้หลัก ลูกอยู่หนี้รอง)
รายการชำระที่ไม่ได้ระบุก้อนหนี้ จะเฉลี่ยตามสัดส่วนให้ **ก้อนระดับบนสุดของบัญชีนั้น** เท่านั้น
```

## 3. `Purchases` — รายการซื้อของ

### ซื้อทีเดียวหลายอย่าง (สั่งออนไลน์)

สั่งของออนไลน์ครั้งเดียวมักได้ของหลายอย่างจากร้านเดียว จึงเก็บได้ใน **แถวเดียว**
โดยแตกรายการย่อยไว้ในคอลัมน์ `รายการในบิล` บรรทัดละหนึ่งรายการ

```
ปั๊มน้ำ 750W | 1 | เครื่อง | 4250
สายไฟ VAF 2x1.5 | 20 | เมตร | 17.5
เทปพันสายไฟ | 3 | ม้วน | 15
```

คั่นด้วย `|` ตามลำดับ **ชื่อ · จำนวน · หน่วย · ราคาต่อหน่วย**
ตั้งใจเก็บเป็นข้อความไม่ใช่ JSON เพราะเปิดชีตพิมพ์แก้เองได้ทันที
กรอกไม่ครบก็ได้ — 3 ช่องคือ `ชื่อ|จำนวน|ราคา` · 2 ช่องคือ `ชื่อ|ราคา` (ถือว่า 1 ชิ้น)

| คอลัมน์ | ความหมาย |
|---|---|
| `รายการในบิล` | รายการย่อยทั้งหมดในคำสั่งซื้อเดียว |
| `ค่าส่ง` · `ส่วนลด` | คิดรวมในยอดบิล |
| `ราคารวม` | **ระบบคิดให้เอง** = ผลรวมรายการย่อย + ค่าส่ง − ส่วนลด |
| `จำนวน` | **ระบบคิดให้เอง** = ผลรวมจำนวนของทุกรายการย่อย |
| `เลขที่คำสั่งซื้อ` | เลขออร์เดอร์จาก Shopee / Lazada ไว้ตามเรื่องทีหลัง |

> รายการที่ซื้อชิ้นเดียวไม่ต้องใส่รายการย่อย กรอกราคาเองได้เหมือนเดิมทุกอย่าง
> `ราคารวม` ยังเป็นตัวเลขที่รายงานทุกหน้าใช้ ของเก่าจึงไม่กระทบเลย

วันที่ซื้อ · ปี · รายการสินค้า · หมวดหมู่ (10 หมวด) · จำนวน · หน่วย · ราคารวม ·
แหล่งที่ซื้อ · ผู้ชำระ · **ประกัน (เดือน)** · **ประกันหมดอายุ** · ห้อง/พื้นที่ ·
ภาพประกอบ · สลิปการโอน · หมายเหตุ

> ใส่ "ประกัน (เดือน)" แล้วระบบคำนวณ "ประกันหมดอายุ" ให้เอง และเตือนล่วงหน้าตาม `warranty_alert_days`

| `webapp_url` | *(จำเอง)* | ที่อยู่ /exec ระบบจดให้ตอนมีคนเปิดเว็บครั้งแรก |
| `admin_token` | *(สุ่ม)* | กุญแจกู้ระบบ — **ไม่ส่งออกไปหน้าเว็บ อย่าแชร์** |
| `view_token` | *(สุ่ม)* | กุญแจลิงก์แชร์ — **ไม่ส่งออกไปหน้าเว็บ** เปลี่ยนใหม่ได้จากเมนู |
| `admin_emails` | *(ว่าง)* | อีเมลที่ให้สิทธิ์ผู้ดูแลเพิ่ม คั่นด้วย `,` |
| `door_code` / `admin_code` | *(ว่าง)* | รหัสเข้าตึก — **ไม่ส่งออกไปหน้าเว็บ** กรอกในชีตเท่านั้น |

> 4 คีย์ท้ายที่ทำตัวหนาไว้ถูกกันไม่ให้อ่านและเขียนผ่านหน้าเว็บโดยสิ้นเชิง (`SECRET_SETTINGS` ใน `Settings.gs`)
> ต่อให้ส่งคำสั่งบันทึกมาตรง ๆ ระบบก็ข้ามให้เงียบ ๆ

## การย้ายโครงสร้างข้อมูล (Migrate.gs)

เมื่อคอลัมน์ใน `SCHEMA` เปลี่ยน การเขียนหัวตารางทับเฉย ๆ จะทำให้ข้อมูลแถวเดิม
เลื่อนไปอยู่ผิดคอลัมน์ `Migrate.gs` จึงอ่านข้อมูลเดิม **โดยอ้างจากชื่อหัวตารางที่มีอยู่จริง**
แล้วเขียนกลับตามลำดับใหม่

ตัวย้ายทำงานอัตโนมัติทั้งตอนรัน `START_HERE` และตอนเปิดเว็บแอปครั้งแรกหลังอัปเดตโค้ด
ทำครั้งเดียวจริง ๆ โดยจำรุ่นไว้ใน Script Property `SCHEMA_VERSION`

> ⚠️ **ลำดับสำคัญมาก** — `runMigrations_()` ต้องรัน **ก่อน** `ensureSheet_` แตะหัวตาราง
> ถ้าเขียนหัวใหม่ทับก่อน ข้อมูลจะยังอยู่ตำแหน่งเดิม แล้วตัวย้ายจะอ่านชื่อหัวใหม่
> ไปเทียบกับข้อมูลตำแหน่งเก่า ทำให้คอลัมน์เลื่อนทั้งแผง (เคยเกิดขึ้นจริงมาแล้ว)
>
> `ensureSheet_` จึงถูกทำให้ **ห้ามเขียนหัวทับเมื่อชีตมีข้อมูลและหัวไม่ตรง** —
> ต้องเรียก `remapSheet_` ย้ายข้อมูลตามชื่อหัวเดิมก่อนเสมอ

| รุ่น | เปลี่ยนอะไร | ข้อมูลเดิมกลายเป็น |
|---|---|---|
| 2 | แยก "จำนวนเงิน + ประเภทการชำระ" เป็น "เงินต้น" กับ "ดอกเบี้ย" | ประเภท = ดอกเบี้ย/ค่าธรรมเนียม → ลงช่องดอกเบี้ย · นอกนั้น → ลงช่องเงินต้น |
| 3 | เพิ่มคอลัมน์ "เป็นส่วนหนึ่งของ" ในชีตก้อนหนี้ | ผูกเงินยืมป้าตาเข้ากับหนี้ซื้อที่ดินให้อัตโนมัติ |

### `REPAIR()` — กู้ข้อมูลที่คอลัมน์เลื่อนไปแล้ว

เมนูในชีต → **🩺 ซ่อมข้อมูลที่คอลัมน์เลื่อน** (หรือรันฟังก์ชัน `REPAIR`)

1. สำรองสภาพปัจจุบันลง Drive ก่อนแตะอะไรทั้งสิ้น
2. ตรวจว่าเลื่อนจริงไหม (ถ้าไม่เลื่อนจะไม่แตะข้อมูล รันซ้ำได้)
3. เลื่อนคอลัมน์กลับที่เดิม โดย**อ่านค่าดิบจากชีตตรง ๆ** ไม่ผ่านการแปลงชนิดข้อมูล
   ไม่งั้นข้อความที่ตกไปอยู่ในช่องตัวเลขจะหายตั้งแต่ตอนอ่าน
4. ยอดตั้งต้นที่ถูก Google Sheets เก็บเป็นวันที่ไปแล้ว แปลงกลับด้วยเลขลำดับวันของ Sheets
5. กู้ "เงินต้น/ดอกเบี้ย" และ "ช่องทาง" ที่หายระหว่างทาง จากข้อมูลตั้งต้น
6. ตรวจยอดแล้วรายงานผลว่าตรงกับที่ควรเป็นหรือไม่
