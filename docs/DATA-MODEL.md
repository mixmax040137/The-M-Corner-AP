# 🗂️ โครงสร้างข้อมูล

ระบบเก็บข้อมูลเป็น **11 แท็บ** ในชีตเดียว — แก้ในชีตโดยตรงได้ ระบบจะอ่านค่าใหม่ทันที
โครงสร้างทั้งหมดนิยามอยู่ในตัวแปร `SCHEMA` ในไฟล์ `src/Config.gs` ที่เดียว
เพิ่ม/ลบคอลัมน์ให้แก้ที่นั่น แล้วรัน `setupSystem()` อีกครั้ง

## 1. `Debts` — ก้อนหนี้

ยอดหนี้ตั้งต้นแต่ละก้อน ทั้งบัญชีหลักและบัญชีรอง

| คอลัมน์ | ชนิด | หมายเหตุ |
|---|---|---|
| รหัส | ข้อความ | สร้างอัตโนมัติ `DEBT-xxxxx` |
| ประเภทบัญชี | ตัวเลือก | `หนี้หลัก` / `หนี้รอง` |
| รายการหนี้ · เจ้าหนี้ · วันที่ก่อหนี้ | | |
| ยอดหนี้ตั้งต้น | เงิน | ผลรวมของทุกก้อนในบัญชี = "ยอดหนี้ทั้งหมด" |
| ดอกเบี้ย/เดือน · กำหนดชำระ · ยอดผ่อนต่อเดือน | | ใช้แสดงผลและประมาณการ |
| สถานะ | ตัวเลือก | `กำลังผ่อน` / `ปิดหนี้แล้ว` / `พักชำระ` |

## 2. `DebtPayments` — รายการโอนใช้หนี้

| คอลัมน์ | ชนิด | หมายเหตุ |
|---|---|---|
| ประเภทบัญชี | ตัวเลือก | ต้องตรงกับก้อนหนี้ |
| วันที่ชำระ · ปี | วันที่ / ตัวเลข | ระบบเติมปีให้จากวันที่ |
| จำนวนเงิน | เงิน | |
| **ประเภทการชำระ** | ตัวเลือก | `เงินต้น` เท่านั้นที่ลดยอดหนี้ · `ดอกเบี้ย` และ `ค่าธรรมเนียม` แสดงแยก |
| รหัสหนี้ | ข้อความ | เว้นว่างได้ — ระบบจะเฉลี่ยตามสัดส่วนยอดตั้งต้นของแต่ละก้อน |
| สลิปการโอน | ไฟล์ | ลิงก์ Drive คั่นด้วยขึ้นบรรทัดใหม่ |

**สูตรที่ระบบใช้**
```
ยอดหนี้ทั้งหมด = Σ ยอดหนี้ตั้งต้น (เฉพาะบัญชีนั้น)
ชำระแล้ว      = Σ จำนวนเงิน ที่ประเภท = "เงินต้น"
คงเหลือ       = ยอดหนี้ทั้งหมด − ชำระแล้ว
ความคืบหน้า    = ชำระแล้ว ÷ ยอดหนี้ทั้งหมด × 100
```

## การรับค่าวันที่

`toDate_()` รองรับทุกรูปแบบที่พบในชีตเดิม:

| รูปแบบ | ตัวอย่าง | ผลลัพธ์ |
|---|---|---|
| ISO | `2026-08-23` | 23 ส.ค. 2026 |

| เดือน/วัน/ปี (แบบอเมริกัน) | `5/20/2026` | 20 พ.ค. 2026 |

## เวอร์ชันเว็บแอป (Artifact) เก็บข้อมูลยังไง

ใช้โครงสร้างเดียวกันทุกอย่าง ต่างกันแค่ที่เก็บ:

| | Google Apps Script | เว็บแอป |
|---|---|---|
| ที่เก็บข้อมูล | แท็บในชีต | ก้อน JSON ฝังอยู่ในหน้าเว็บ (`window.__SEED__`) |
| ไฟล์แนบ | ไฟล์ใน Google Drive | รูปย่อเป็น data URI ฝังในหน้า (ย่อเหลือด้านยาว 1,100 px คุณภาพ 72%) |
| การบันทึก | เขียนลงชีตทันที | ประกอบเอกสารใหม่แล้วเผยแพร่ทับตัวเอง |
| เพดานข้อมูล | เท่าที่ Google Sheet รับได้ | ~14 MB ต่อหน้า (ระบบเตือนก่อนถึง) |

ชั้นที่ต่างกันคือฟังก์ชันไม่กี่ตัวใน `Util.gs` (`readRows_` `insertRow_` `updateRow_` `deleteRow_` `bulkInsert_`)
ซึ่ง `artifact/runtime.js` เขียนทับด้วยเวอร์ชันที่ทำงานกับข้อมูลในหน่วยความจำ — ตรรกะธุรกิจทั้งหมดใช้ร่วมกันได้เลย

## ระบบสิทธิ์เข้าใช้งาน

เว็บแอป deploy แบบ **Anyone** เพื่อให้แชร์ให้คนที่ไม่มีบัญชี Google ดูได้
สิทธิ์จึงคุมด้วยกุญแจในลิงก์ ไม่ใช่ด้วยบัญชี Google

| เปิดด้วย | บทบาท | อ่านข้อมูล | แก้ข้อมูล | เห็นลิงก์ Google Sheet |
|---|---|:---:|:---:|:---:|
| `?key=<admin_token>` | `admin` | ✅ | ✅ | ✅ |
| `?key=<view_token>` | `viewer` | ✅ | ❌ | ❌ |
| ไม่มี key / key ผิด | `none` | ❌ | ❌ | ❌ |
| เจ้าของชีต (ล็อกอินอยู่) | `admin` | ✅ | ✅ | ✅ |

การกันสิทธิ์อยู่ในฟังก์ชัน `api()` ของ `Api.gs` ซึ่งเรียก `requireRole_()` **ก่อน**
ทำงานทุกครั้ง ไม่ใช่แค่ซ่อนปุ่มในหน้าเว็บ — คำสั่งที่ตรงกับ `MUTATING_ACTIONS`
(`.save` `.delete` `.import` `.bulkBook` `.send` `.rotateToken` `.backupNow`)
ต้องเป็น `admin` เท่านั้น

ถ้าลิงก์แชร์หลุด: เมนูในชีต → **🔁 ออกลิงก์แชร์ใหม่** กุญแจเดิมจะใช้ไม่ได้ทันที
(กุญแจผู้ดูแลไม่ถูกกระทบ)

## การอัปเดตแบบสด

`app.version` คืนเวลาที่ไฟล์ชีตถูกแก้ล่าสุด (`DriveApp...getLastUpdated()`)
หน้าเว็บเรียกทุก `refresh_seconds` วินาที ถ้าค่าเปลี่ยนก็โหลดข้อมูลของหน้านั้นใหม่

ครอบคลุมทั้งการแก้ผ่านหน้าเว็บและการพิมพ์แก้ในชีตโดยตรง
ระบบจะไม่รีเฟรชขณะที่กำลังเปิดฟอร์มกรอกข้อมูลอยู่ และหยุดเช็คเมื่อสลับแท็บไปทำอย่างอื่น
